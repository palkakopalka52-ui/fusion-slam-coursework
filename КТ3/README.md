# КТ3 · Библиотека плоского SLAM

`slam_lab` совместно оценивает позы, координаты ориентиров и постоянное смещение гироскопа. Ядру нужен NumPy. Эксперименты используют SciPy для независимой проверки оптимума, pandas для таблиц и Matplotlib для графиков. Встраивание здесь означает вызов библиотеки из программы робота. Время на целевой плате и работу в реальном времени предстоит измерять отдельно.

## Встраивание

```python
from slam_lab import Factor, Graph, solve

# Пример двух поз. Камера и колёса измерили тот же интервал.
observations = (
    Factor("wheel", 0, 1, (0.54, 0.0, 0.02), (0.09, 0.04, 0.05)),
    Factor("vo",    0, 1, (0.48, 0.0, 0.01), (0.035, 0.035, 0.025)),
    Factor("gyro",  0, 1, (0.04,), (0.012,), dt=1.0),
    Factor("beacon", 0, 0, (2.00, 0.4), (0.065, 0.028)),
    Factor("beacon", 1, 0, (1.55, 0.5), (0.065, 0.028)),
)
graph = Graph(poses=2, landmarks=1, factors=observations)
fit = solve(graph)
print(fit.poses[-1], fit.landmarks[0], fit.bias, fit.status)
```

Индексы поз и ориентиров начинаются с нуля. В колёсном, визуальном и петлевом факторе вектор измерения содержит продольный и боковой перенос в метрах и относительный курс в радианах. У гироскопа измерение представляет собой накопленный за `dt` угол, `dt` в секундах. У ориентира вход — дальность и пеленг, `j` — номер ориентира. Стандартные отклонения задаются в единицах каждой компоненты. Первая поза фиксирована в начале координат. Камерные приращения нужно заранее перевести в рамку базы и согласовать по времени.

`Problem.initial()` строит приближение по непрерывной цепочке колёсных факторов и наблюдениям ориентиров. `solve(graph, delta=None)` включает WLS. По умолчанию используется блочный Huber с порогом 2,5. Число линейных решений, число отказов, история принятой цели и причина остановки есть в объекте результата.

В `results/measurements.json` лежат только измерения проблемного маршрута 23, в `reference.npz` отдельно сохранён его эталон. Для загрузки формы JSON подходят `Graph(d["poses"], d["landmarks"], tuple(Factor(**f) for f in d["factors"]))`. Синтетический генератор, оценщик и решатель находятся в разных модулях.
